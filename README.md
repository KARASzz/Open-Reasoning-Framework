# Open Reasoning Framework（ORF，暂定名）

**开源认知分析引擎**——将哲学、管理学、经济学、认知科学、博弈论等领域中可复用的核心思维方式，拆解为机器可调用、可组合、可审计、可证伪的"推理算子"，用于分析现实中的复杂问题。

> ORF 不负责替用户思考。它负责：**让用户更难轻易相信自己的第一个答案。**

## 它回答的不是

> "孔子怎么看这个问题？"

## 它回答的是

> "这个问题如果分别从角色、利益、权力、激励、因果、博弈、认知偏差、证伪等角度分析，会得到什么不同解释？这些解释之间哪里冲突？还缺什么证据？什么事实出现时应当推翻当前判断？"

## 不是什么

- 不是哲学百科全书，不是名人观点问答，不是角色扮演聊天机器人；
- 不是一个大型 Prompt 集合——如果只是提示词打包，则项目失败。

项目真正的护城河是"引擎四层论"：SQL 语句本身只是文本，但数据库不是文本文件集合——让 SQL 有价值的是引擎、约束和事务。同理：

1. **Schema 校验**：结构正确性强制；
2. **编排纪律**：选择、并行、对抗角色指派由 Runtime 决定；
3. **契约强制**：输出缺字段即拒绝重跑，攻击者不得沉默；
4. **评测回归**：对基线持续对照，逻辑漂移被测试捕获。

## 核心概念

| 单位 | 定义 |
|---|---|
| **Framework（分析框架）** | 分析镜头，含边界判据（"我回答什么 / 我不回答什么"） |
| **Operator（推理算子）** | 类型化转换器：类型化输入 → 类型化输出，LLM 是填空的推理引擎 |
| **Combinator（执行组合器）** | 执行组合模式，首个实例为认知差分析（立场参数化执行 + 结构化 diff） |

一次完整分析的所有中间产物（事实、假设、证据、冲突）累积为一张带溯源的**类型化推理图**——审计（哪些事实来自用户、哪些是模型推断、哪些框架冲突）是推理图的天然属性。

## 核心机制

- **Framework Selector**：LLM 选择 3～7 个最相关框架，强制输出逐个命中理由，理由可被用户质疑；
- **Cross-Audit（思想互审）**：并行单轮——各框架并行产出结论，攻击者互不可见地并行攻击；攻击者必须实质攻击或声明"无攻击 + 已查项"；
- **证伪过关**：每个重大假设必须带可推翻条件，否则不得进入综合；
- **综合硬规则**：不得合并仍有未被反驳竞争假设的局面；"证据不足，无法判断主因"是一等合法输出；
- **无状态再分析**：用户补充证据后携带上一次分析再调用，仅重审受影响假设。

## 当前状态

原型阶段（v0.2 已定稿），内容建设进行中，尚未包含运行时代码。

已完成：

- **4 个 JSON Schema**（`schemas/`）：framework / operator / combinator / output；
- **8 个 Framework 定义**（`frameworks/`）：角色与正名、利益结构、激励结构、权力关系、认知偏差、有限理性、系统反馈、证伪，均含边界判据；
- **50 个 Operator**：8 个框架均已具备首批算子组，均为类型化转换器；
- **认知差组合器**（`combinators/cognitive_gap/`）：立场参数化执行 + 结构化 diff；
- **内容校验工具**（`tools/validate.py`）：Schema 校验 + 交叉引用检查，`python3 tools/validate.py --strict`；
- **10 个评测种子案例**（`evaluations/cases/`）：六类真实脏问题。

## MVP 范围

第一批 8 个分析框架：角色与正名、利益结构、激励结构、权力关系、认知偏差、有限理性、系统反馈、证伪。每个框架 5～15 个算子，总量控制在 60～100 个高质量 Operators。**质量比数量重要。**

## 待验证的核心假设

> 将高质量思维框架拆解为结构化 Reasoning Operators，并进行多框架互审，是否能够比裸 LLM 和大型系统提示词更稳定地发现复杂现实问题中的遗漏变量、反例和可推翻条件？

如果不成立：停止扩张。如果成立：再讨论工程化、社区、API、可视化和生态。
